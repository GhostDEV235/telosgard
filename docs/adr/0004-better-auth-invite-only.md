# Sign-in with Better Auth (email + password), invite-only

*Decided 2026-11-12. Supersedes the Cloudflare Access part of [ADR 0003](0003-cloudflare-pages-d1-access.md).*

Telosgard has its own accounts: **Better Auth 1.7.14** runs inside the Worker at `/api/auth/*`, with its `user`, `session`, `account`, `verification` and `rateLimit` tables in D1 (migration `0003_auth.sql`, generated by the library itself). People sign in with **email + password** (at least 10 characters, stored hashed); sessions are a same-origin cookie. **Sign-up is invite-only**: the owner creates a single-use link (`/#join-<token>`, valid 7 days, only its SHA-256 stored) and sends it however they like; without a valid token, sign-up is refused. An address in the `OWNER_EMAILS` secret may sign up without one (the owner's own account, via `/#join`). Cloudflare Access is not used.

## Considered Options

- **Cloudflare Access only.** Dropped: the Learner wants testers to have plain accounts in the app, with no Cloudflare login in front.
- **Email codes or emailed magic links.** Deferred: they need an email-sending service and a domain set up for it; the Learner wants Cloudflare only for now. Invite links are shared by hand instead.
- **Google sign-in.** Deferred: needs a Google Cloud OAuth app outside Cloudflare.
- **Open sign-up.** Rejected: anyone could spend the Learner's Anthropic key (50 calls a day each).

## Consequences

- No self-service password reset yet (no email sending); the owner resets a tester's password for them.
- Better Auth's built-in rate limit (stored in D1, keyed by `cf-connecting-ip`) slows password guessing and sign-up floods. Its telemetry is switched off.
- Secrets on the Worker: `BETTER_AUTH_SECRET` (signs sessions), `OWNER_EMAILS`, `ANTHROPIC_API_KEY`. `DEV_USER` stays for local development and tests, and only ever applies to localhost.
- Owner and testers keep separate Claude caps (300 / 50 calls a day).
